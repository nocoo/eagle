## 观察与调整

v1 原始四组都生成了合法 JSON，但摘要过长、缺失证据反复出现，稀疏资源样例使用了“短暂”“持续”等无依据的时间描述。注入样例没有执行恶意指令，但复述了恶意字符串；这是输出卫生问题，不是已发生指令劫持。该样例初版 observations 与 payload 时间差 1 分钟，已修正；修正后的 v1 单独复跑还出现一次非法 JSON，未保存为有效报告。

真实 51 条语义记录分为三块。v1 首块达到 8,192 output tokens，返回 `finish_reason=length`，JSON 截断，未写入 D1。第一版 v2 草稿缩短了输出，但模型把规定的文本字段改为数组/对象，四组均被 schema 拒绝；随后增加明确类型示例和“最终报告／分块整理”阶段标识。中间版本八次自动检查通过，但人工复读仍发现“任务已处于完成态”的含混表述；较大输入也继续暴露分块冗长。最终明确使用“面板标记”，并将中间步骤改为紧凑证据整理。

`eagle-hourly-zh-v2` 将摘要 120～220 字设为目标，prompt 要求不超过 400 字；合并重复 Pane/task 语义；缺失项集中说明；禁止把样本外推为持续状态；保留来源、任务与时间边界，重要结论就近引用。分块不写高管摘要，只保留身份、关键变化及证据。严格校验全部字段后，如果只有摘要超过 400 字，最多追加一次压缩并重新校验，其他章节不变。实际回放曾将 525 字压缩为 406 字，其余内容有效，因此最终校验保留到 600 字的容差；超过仍失败，不循环调用模型。截断响应明确拒绝；未知内联引用拒绝。DO 生成版本加入模板版本，升级后相同输入可重生成，之后仍幂等；过期但尚未归档的 pending 结果保留原元数据。

v2 真实入库后人工审阅发现：模型将前一天的 CI queued 消息写成当前未解除的阻塞，即使其他章节已注明仅是终端来源。补充第五组 eval 复现了这一问题，随后 `eagle-hourly-zh-v3` 明确要求保留嵌套 evidence 自己的 observedAt，新 Manager 时间不刷新旧事实；旧 blocker 只列待核实，摘要也不能丢掉来源限定；取消任务不建议自行重开。新样例在 v3 中明确写出“不能据此断定 CI 现在仍排队或仍被阻塞”，真实阻塞栏说明没有本小时独立证据。

## 重跑

先启动本地 Worker，在设置页配置 AI；脚本只读取 `.wrangler/state/v3/do/eagle-MachineDirectory` 和 `.dev.vars`，密钥只在内存解密，不打印，也不写进评测文件。

```sh
node scripts/eval-hourly.ts trial
# 可仅重跑一组
node scripts/eval-hourly.ts trial weak-hints-conflict
```

如本机访问模型需要代理，可按本机网络环境设置 HTTPS_PROXY 和 NODE_USE_ENV_PROXY。指标、原始 prompt 和经过密钥检查及 schema 校验的结果保存在忽略目录 `.local/hourly-eval/<label>/`；失败只记录错误类别。`manualChecks` 是需要人工阅读的判据，不是模型自动打出的通过分数。

证据目录：`baseline/`、`baseline-corrected/`、`v2/`（被拒绝的中间版本）、`v2-format/`、`v2-confirm/`、`final/`、`final-recheck/`、`bounded/`、`final-validated/`（v2）、`stale-before/`（新增样例的 v2 失败）、`v3-final/`（上表最终版本）。期间有短暂上游连接错误，单独连接检查恢复后才继续；未修改密钥或切换模型。失败响应不会绕过校验自动入库，只有已验证报告的长摘要允许一次有界改写。完整回归：69 项单元/接口检查、44 项浏览器检查；9 月 20 日恢复任务后重新通过 `npm run check`。

Grok 只读 Review 发现 eval 解密未检查当前 endpoint 的缺口；先以失败回归复现，再让共享 `unsealAiKey` 强制校验目标地址，eval 与正式路径都使用该保护。
